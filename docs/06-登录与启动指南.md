# 登录与启动指南

> 核心结论：**本工具不接管登录，也没有账号密码输入环节。** 登录始终由微信/QQ 客户端自己完成，脚本只是"搭便车"。

---

## 一、为什么不需要输入账号密码

上一版方案（外部进程直连 WSS）需要自己处理登录：扫码 → `login_buffer` → 复刻 mmtls 私有协议换 `code`。**这条路已经被放弃了**——工程量极大且随客户端升级失效。

现在走的是**运行时注入**：CDP 接进正在运行的游戏，直接调用它自己的网络层。

```
微信用 户 正 常 登 录 并 进 入 游 戏
        ↓（游戏自己持有登录态、自己心跳、自己反作弊）
   调试端口暴露出 CDP 通道
        ↓（本工具从这里接入）
   抓取 __netInst → 注入 __bot → 开始挂机
```

所以**登录 = 你在微信里正常打开 QQ 农场**。工具侧不做任何账号操作，也**不接触** cookie、token、code。

---

## 二、前置条件

| 条件 | 说明 |
|---|---|
| **1. 微信/QQ 客户端已打开** | PC 端，能在里面打开小游戏 |
| **2. QQ 农场已进入过** | 至少成功进过一次游戏，且**保持页面打开** |
| **3. 调试端口已开启** | 当前环境由 `First` 调试器提供（`127.0.0.1:62000`） |

> **游戏页面必须保持打开。** 关掉游戏窗口 = 没有运行时 = 无法挂机。这是本方案的固有约束。

---

## 三、完整启动步骤

### 第 1 步：进入游戏（这一步就是「登录」）

在微信里打开 **QQ 经典农场**，正常进入农场界面。

- 首次进入需要走微信授权，那是微信自己弹的，按提示点即可
- 进入后能看到自己的地、好友，说明登录态已就绪

### 第 2 步：确认调试端口

本机是 `First - WeChat MiniProgram Debugger`（`D:\first\First.exe`）：

- 端口 **62000** 是 CDP 端点
- 端口 **18927** 是它的 Web UI
- 如需附加小程序目标：打开 First 窗口 → **◎ 服务目标** → 刷新 → 选中 → **附加**

如果曾经在 Chrome 里打开过 `devtools://devtools/bundled/inspector.html?ws=127.0.0.1:62000`，**记得关掉那个标签页**——62000 是单客户端独占，被占住时本工具收不到消息。

### 第 3 步：启动挂机

```bash
# 交互模式（推荐首次使用）
node tools/tui.mjs

# 指定 gid 并自动开始挂机（无人值守）
node tools/tui.mjs --yes -m --gid 1229136306

# 无界面跑一轮后退出（适合定时任务）
node tools/tui.mjs --once
```

TUI 启动时会自动完成：

```
🔌 连接 CDP ws://127.0.0.1:62000
🎮 游戏上下文 ctx=7 (keys=125)
✅ 桥接就绪 ctx=7
🔑 gid = 1229136306
✅ 账号 shilin (lv17) gid=1229136306 土地=24 好友=14
✅ 登录态已就绪，随时可挂机（[m] 或 /挂机）
```

看到「**登录态已就绪**」就可以按 `m` 开始挂机，或用 `-m` 参数让它自动开始。

## 四、断线了要重新登录吗

**大部分情况不需要，游戏会自己处理。**

| 场景 | 要重登吗 | 谁处理 |
|---|---|---|
| WSS 网络抖动 | **不需要**（游戏自动重连并重取 code） | 游戏网络层，最多重试 3 次 |
| 请求超时 | 不需要 | 游戏自己处理 |
| **游戏页面刷新 / 重启** | 游戏自动重新登录 | **本工具自动重抓注入（约 20s）** |
| **微信客户端关闭** | **需要** | **人工重开客户端并进游戏** |
| 挂机脚本崩溃 | 不需要 | 重跑脚本即可（注入仍在游戏内） |
| 调试端口关闭 | 不需要 | 重开端口 + 脚本 `/刷新` |

依据：游戏的 `reconnect()` 里**没有任何生成 code 的逻辑**，code 由业务层在重连时重新取——所以「重连要重新登录」这件事是游戏自己完成的。而 `__netInst` 是长生命周期对象，重连只换内部 socket，注入继续有效。

**唯一的自动化盲区**：游戏页面刷新后 `__netBot` 会丢失，此时 `Bridge.ensure()` 会自动重走「抓 `__netInst` → 注入」流程，**实测约 22 秒恢复，无需人工**。

**唯一需要人工的**：微信客户端被关掉。这种情况重新打开客户端、进一次游戏即可。

## 五、常见问题

**Q：提示「CDP 连接失败」**
调试端口没开，或被别的客户端占用。检查 62000 是否在监听、关掉 Chrome 里的 devtools 页面。

**Q：提示「未找到游戏主上下文（tsdk+cc）」**
游戏没运行，或页面已关闭。回到第 1 步重新进入游戏。

**Q：提示「断点未命中（等待 45s）」**
游戏在运行但没产生任何请求（可能卡在某个界面）。游戏心跳每 25 秒一次，正常情况下必命中。可以 `/刷新` 重试。

**Q：gid 解析不出来**
第一次会等一次心跳（最长 30s）。也可以 `--gid <你的gid>` 直接用 `/好友` 里查到的值。

**Q：挂了很久没动静**
看日志区是否有 ⚠️。多半是种子用尽（会自动购买，但金币不够时会失败），或所有地都在生长中。

**Q：挂机时能玩手机/关电脑吗**
取决于游戏客户端。**关掉客户端等于断掉运行时**，挂机随即停止。电脑需要保持开机 + 游戏页面保持打开。

---

## 六、一句话总结

**在微信里正常进游戏 → 确保 62000 端口可用 → `node tools/tui.mjs -m`。**

登录是微信的事，工具只负责在游戏运行时接进去干活。
