# 调试端口开启指南

> 本工具**不绑定任何特定工具**，只需要一个可用的 CDP 端点。任选下面一种方式暴露端口即可。

---

## 一、为什么需要这一步

本工具走的是**运行时注入**：通过 Chrome DevTools Protocol 接进正在运行的小游戏，直接调用它自己的网络层。所以需要一个 CDP 端点。

微信小程序框架（WMPF）**本身带官方 Remote Debug 机制**——微信开发者工具用的就是它。但默认关闭且有限制，需要**一次性用工具把它解开**。

> 这一步是**环境准备**，不是每次挂机都要做。工具启动后端口会一直存在，只要微信不重启。

---

## 二、方案对比

| 方案 | 依赖 | 适用 | 说明 |
|---|---|---|---|
| **WMPFDebugger** ⭐ | Node.js 22+ | Win / macOS / Linux | 开源，**支持版本最全**，当前 WMPF `19841` 在支持列表内 |
| **WeChatOpenDevTools** | Python | Windows | 开源，中文文档友好 |
| **First** | 无（单 exe） | Windows | 免安装，当前环境用的就是这个（`D:\first\First.exe`） |
| WeChatDevTools | 无（放 dll） | Windows | 「只需放置一个 dll」 |
| WMPFDebugger-arm | Node.js | macOS ARM | 苹果芯片专用 |

**端口约定**：这些工具**默认都暴露在 `62000`**，这也是本工具的默认端口。如果你的工具用了别的端口，用 `--port` 指定即可。

## 三、推荐方案：WMPFDebugger

```bash
# 1. 需要 Node.js 22+
git clone https://github.com/evi0s/WMPFDebugger
cd WMPFDebugger
yarn

# 2. 启动调试服务器 + 注入 hook（保持运行）
npx ts-node src/index.ts

# 3. 现在打开小游戏（顺序很重要！先启动工具，再进游戏）

# 4. 验证端口
node tools/port-find.mjs
```

**注意事项（官方原文）**：
> 启动调试服务器后，**需要先打开小程序再启动 devtools**，否则可能要杀掉进程重做步骤 2–4。

**看看自己的 WMPF 版本**：任务管理器 → `WeChatAppEx` → 右键「打开文件位置」→ 路径里 `RadiumWMPF` 后面那个数字就是（本机是 `19841`）。

## 六、验证与使用

### 自动查找端口

不确定端口时，直接扫：

```bash
node tools/port-find.mjs
```

输出示例：

```
✓ 发现 1 个 CDP 端点：
   127.0.0.1:62000  (可用)

推荐使用端口：62000
  node tools/tui.mjs --port 62000
```

### 启动挂机

```bash
node tools/tui.mjs --yes -m          # 自动挂机
```

**即使端口不是 62000 也不用改配置**——`Bridge` 在默认端口连不上时会**自动扫描其他常见端口**（62000–62010、9420/9421、9222/9229），实测 1.5 秒内完成切换。

### 完整顺序

```
1. 启动调试工具（WMPFDebugger / First / ...）   → 端口 62000 就绪
2. 在微信里打开 QQ 农场并进入                    → 游戏运行时就绪
3. node tools/tui.mjs -m                        → 开始挂机
```

**顺序不能反**：调试工具要在游戏之前启动（否则 hook 注入不到运行时）。

## 七、常见问题

**Q：提示 CDP 连接失败**
1. 调试工具没启动 → 启动它
2. 工具启动了但游戏比工具先开 → 关掉游戏重开（hook 需要先注入）
3. 62000 被占用（比如 Chrome 开着 `devtools://...?ws=127.0.0.1:62000`）→ 关掉那个标签页
4. 端口不是 62000 → `node tools/port-find.mjs` 找一下

**Q：工具启动后游戏里能用，但脚本连不上**
62000 是**单客户端独占**。有别的调试器（例如浏览器 devtools 页面）连着时，脚本能建连但收不到消息。关掉其他调试客户端。

**Q：微信更新后失效**
WMPF 版本变了，需要等工具适配新版本。WMPFDebugger 支持 `--auto-detect` 自动适配（beta），或到其仓库提交新版本适配请求。

**Q：能不用工具吗**
不能。WMPF 的 Remote Debug 默认关闭且有校验，必须有一步注入才能解开。这一环无法从脚本侧绕过。

## 八、小结

| 项 | 说明 |
|---|---|
| **必需** | 一个调试端口暴露工具（任选） |
| **端口** | 默认 62000，可自动发现 |
| **顺序** | 先工具 → 后游戏 → 再脚本 |
| **频率** | 工具启动一次即可，微信重启后需重做 |
| **脚本侧** | 无需改动，`--port` 或用自动发现 |
