# QQ 农场挂机 · 运行时注入方案（首选方案）

> 本文取代《02-架构设计》中的加密逆向路线。原方案降级为「备选 B」。
> 依据：2026-09-25 通过 `devtools://...ws=127.0.0.1:62000` 对运行中的游戏实例实测。

---

## 一、结论：整条加密逆向链路可以跳过

通过 CDP 接入微信 XWEB 调试端口后，实测确认：**游戏把「加密 → token → seq → meta → 发送」全部封装在一个方法里，且入参是明文 protobuf。**

```js
__netInst.send(
  plainProtobuf,               // ① 明文 Uint8Array，未加密
  'Heartbeat',                 // ② method_name
  callback,                    // ③ 回调 function({meta, body})
  'gamepb.userpb.UserService'  // ④ service_name（完整包名）
)
```

实测日志（hook 真实调用所得）：

```
a=Uint8Array(len=28) 08b2c38cca041212312e31342e322e31335f32303236303932321800
b=string:Heartbeat
c=fn
d=string:gamepb.userpb.UserService
```

**这意味着**：不需要提取 `tsdk.wasm`、不需要复刻 mmtls 登录、不需要实现任何加解密算法。挂机脚本只负责构造明文 protobuf 并交给游戏。

### 闭环验证

已实测发送 `AllLands` 并成功收到解密后响应：

```
调用: __netInst.send(new Uint8Array(0), 'AllLands', cb, 'gamepb.plantpb.PlantService')
响应: { meta:{ service_name:'gamepb.plantpb.PlantService', method_name:'AllLands',
               message_type:'2', client_seq:'200', server_seq:'200' },
        body: 2196 字节明文 protobuf }
```

明文 body 中直接可读出作物名：`狗尾草`、`泡泡棉花糖`，以及 13 块地的完整状态。
存档：`out/proto/AllLandsReply.bin`

## 三、架构

```
┌────────────────────────────────────────────────────────┐
│  挂机进程 (Node.js, 外部)                                │
│  ├─ protobufjs + proto 定义   → 业务报文的编解码          │
│  ├─ CDP 客户端 (ws://127.0.0.1:62000)                    │
│  ├─ 任务调度 / 限流 / 状态缓存                            │
│  └─ CLI                                                   │
└──────────────────────┬─────────────────────────────────┘
                       │ Runtime.evaluate（传 hex 字符串）
┌──────────────────────▼─────────────────────────────────┐
│  游戏运行时（Cocos + TSDK，已登录态）                     │
│  __bot.call(service, method, bodyHex)                   │
│    → __netInst.send(明文Uint8Array, method, cb, service) │
│      → TSDK 加密 → token → seq → meta → WSS             │
│    ← 响应解密 → 回调 {meta, body}                        │
└────────────────────────────────────────────────────────┘
```

**职责切分**：
- 页面内只放一个瘦适配层（收发 hex），业务逻辑全在外部，便于开发调试
- 加密/token/seq/心跳/ACE 全部交给游戏本体，零维护成本
- protobuf 编解码放外部，用官方 proto 定义，不做手工字节拼装

## 四、注入的适配层

一次性注入到 `ctx=3`（游戏主上下文），之后可长期驻留：

```js
globalThis.__bot = {
  net: null,
  ready() {
    this.net = globalThis.__netInst;
    return !!this.net;
  },
  // 发请求：bodyHex 为明文 protobuf 的 hex，回 {meta, bodyHex}
  call(service, method, bodyHex) {
    const net = this.net || globalThis.__netInst;
    if (!net) return Promise.reject(new Error('net not ready'));
    const bytes = bodyHex ? new Uint8Array(bodyHex.match(/../g).map(h => parseInt(h, 16)))
                          : new Uint8Array(0);
    return new Promise((resolve, reject) => {
      const timer = setTimeout(() => reject(new Error('timeout ' + method)), 15000);
      net.send(bytes, method, (r) => {
        clearTimeout(timer);
        let out = null;
        if (r && r.body) {
          const u8 = r.body instanceof ArrayBuffer
            ? new Uint8Array(r.body)
            : new Uint8Array(r.body.buffer, r.body.byteOffset, r.body.byteLength);
          out = Array.from(u8).map(b => b.toString(16).padStart(2, '0')).join('');
        }
        resolve({ meta: r && r.meta ? {
          svc: r.meta.service_name, mth: r.meta.method_name,
          type: r.meta.message_type, cseq: r.meta.client_seq, sseq: r.meta.server_seq,
        } : null, bodyHex: out });
      }, service);
    });
  },
  // 连接与账号状态
  status() {
    const n = this.net || globalThis.__netInst;
    return n ? { state: n._state, url: n._url, cseq: n.clientSeq, sseq: n.serverSeq } : null;
  },
};
```

**注意 `client_seq` 由游戏自增**，脚本不要干预。

## 五、外部调用（Node.js 侧）

```js
// cdp-call.mjs 的核心
async function call(service, method, bodyBytes) {
  const bodyHex = Buffer.from(bodyBytes).toString('hex');
  const expr = `globalThis.__bot.call(${JSON.stringify(service)},${JSON.stringify(method)},${JSON.stringify(bodyHex)})
                  .then(r => JSON.stringify(r))`;
  const r = await cdp('Runtime.evaluate', {
    expression: expr, contextId: 3, awaitPromise: true, returnByValue: true,
  });
  if (r.exceptionDetails) throw new Error(r.exceptionDetails.exception?.description);
  const out = JSON.parse(r.result.value);
  return { meta: out.meta, body: out.bodyHex ? Buffer.from(out.bodyHex, 'hex') : null };
}
```

### 四个需求的直接实现

```js
// 需求 1：查空地块 / 一键收获 / 种植
const all = await call('gamepb.plantpb.PlantService', 'AllLands', AllLandsRequest.encode({}).finish());
const rep = AllLandsReply.decode(all.body);
const empty  = rep.lands.filter(l => !l.plant || l.plant.id === 0).map(l => l.id);
const ripe   = rep.lands.filter(l => isRipe(l)).map(l => l.id);

await call('gamepb.plantpb.PlantService', 'Harvest',
  HarvestRequest.encode({ land_ids: ripe, host_gid: myGid, is_all: true }).finish());

await call('gamepb.plantpb.PlantService', 'Plant', encodePlantRequest(seedId, empty));

// 需求 2：好友列表 / 拜访 / 清理
const fr = await call('gamepb.friendpb.FriendService', 'GetAll', GetAllFriendsRequest.encode({}).finish());
const friends = GetAllFriendsReply.decode(fr.body).game_friends;
await call('gamepb.visitpb.VisitService', 'Enter',
  VisitEnterRequest.encode({ host_gid: gid, reason: 2 }).finish());
await call('gamepb.friendpb.FriendService', 'DelFriend',
  DelFriendRequest.encode({ friend_gid: gid }).finish());

// 需求 3：撒虫 / 撒草 / 偷菜
await call('gamepb.plantpb.PlantService', 'PutInsects',
  PutInsectsRequest.encode({ land_ids: [landId], host_gid: gid }).finish());
await call('gamepb.plantpb.PlantService', 'PutWeeds',
  PutWeedsRequest.encode({ land_ids: [landId], host_gid: gid }).finish());
```

## 八、风险与注意

| 风险 | 说明与对策 |
|---|---|
| 页面刷新丢失全部注入 | 用 `grab-net.mjs` + 适配层重新注入，做成启动脚本 |
| 断点暂停游戏 | 命中后立即 `Debugger.resume`，窗口为毫秒级 |
| 调试端口依赖 | 62000 由微信的远程调试开关提供，客户端重启后需重新开启 |
| 速率与每日上限 | 放虫/放草逐块发，间隔 80~160ms；`1001046` 触发当日熔断 |
| 写操作超时不可重发 | 改为下轮 `AllLands` 对账，避免重复收获 |
| 与手动操作冲突 | 挂机期间建议关闭手动操作，或加互斥锁 |
| ACE 反作弊 | 不干预游戏的 ACE 调度（5/25/30/150s），只当旁观者 |

**核心优势**：由于完全复用游戏自身的加密与反作弊链路，本方案不产生「加密特征异常」这类风险——所有报文与真实客户端逐字节同构。

## 十、调试链路与恢复（实测）

### 端口占用关系

本机运行的是 **First - WeChat MiniProgram Debugger**（`D:\first\First.exe`，Spade-sec），不是微信原生调试端口：

| 端口 | 用途 | 占用 |
|---|---|---|
| `62000` | **CDP WebSocket 端点**（`Targets.attach` 后转发目标） | 单客户端 |
| `18927` | First 的 Web UI（Vue SPA） | HTTP |
| `9421` | 另一个 WS 端点（同 62000 一样返回 426） | 未知用途 |

**实测结论：62000 是单客户端独占。** 当 Chrome 打开 `devtools://devtools/bundled/inspector.html?ws=127.0.0.1:62000` 后，它会占住通道——新连接能建立 TCP/WS 握手，但**收不到任何消息、`Runtime.enable` 无响应**。

### First 自带的能力（可直接利用）

| 菜单 | 前端调用 | 说明 |
|---|---|---|
| ⚙ **MCP** | `mcp.start({port, cdp_port})` / `mcp.status` | **开启后提供 `http://127.0.0.1:<port>/v1/`，界面原文：「AI 可通过 HTTP API 自主调试和分析小程序」** |
| ◎ **服务目标** | `targets.list` / `targets.attach({target_id})` | 列出并附加调试目标 |
| ◈ **Hook** | `hook.list` / `hook.inject({filename})` / `hook.setGlobal` | 把 JS 放进 `hook_scripts/` 即可注入到小程序 |
| ◇ 调试开关 | — | 控制 frida / miniapp / devtools 三档 |

MCP 默认端口 **4554**（实测当前未开启）。Hook 脚本格式就是普通 JS，例如官方样例：

```js
console.log("[Hook 测试] Hello from hook_scripts! 注入成功");
```

> Hook 页面自带警告：**「JS 注入后无法真正撤销，需刷新页面」**。

### 两条恢复路径

**路径 A（推荐）**：在 First 窗口点「⚙ MCP」→ 打开「MCP 服务」开关。之后挂机进程改走 `http://127.0.0.1:4554/v1/`，不再与 Chrome 争抢 62000。

**路径 B（最快）**：关闭 Chrome 中 `devtools://...?ws=127.0.0.1:62000` 标签页释放端口，重新执行 `tools/grab-net.mjs` 注入。

**路径 C（无需通道）**：把自包含挂机 JS 放入 `hook_scripts/`，用 First 的 Hook 注入到小程序页面内运行。

### 注入内容会丢失

游戏页面刷新、或调试会话重连后，`globalThis.__netInst` 与 `globalThis.__bot` **全部丢失**，必须重跑：

```
node tools/grab-net.mjs          # 断点抓 __netInst（心跳 25s 内必命中）
node tools/bot.mjs status        # 自动注入 __bot 并显示状态
```

## 十一、与原方案的对比

| 维度 | 原方案（外部进程） | 本方案（运行时注入） |
|---|---|---|
| 提取 `tsdk.wasm` | 必需 | **不需要** |
| 复刻登录（mmtls/扫码） | 必需 | **不需要** |
| 实现加密算法 | 必需 | **不需要** |
| 心跳 / ACE 维护 | 需自建 | **游戏自带** |
| 协议可见性 | 需解密 | **明文直读** |
| 与官方客户端行为一致性 | 低 | **逐字节同构** |
| 主要依赖 | wasm + 登录通道 | 调试端口 + 注入 |
| 工程周期 | 数周（mmtls 是硬骨头） | **数天** |
