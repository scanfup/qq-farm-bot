## 二、实测报文（可直接复现）

### 1. 收获

```
req 0a0101108bddd4df041801
      0a 01 01            field1 land_ids  = [1]          (packed)
      10 8bddd4df04       field2 host_gid  = 1274359435   (自己)
      18 01               field3 is_all    = true
resp 178 B → 含 LandInfo(id=1)，operation_limits id10001:1
```

### 2. 种植 ★ 关键坑

```
✗ 失败：120a08a29c01120403040506
         field2.items = PlantItem{ seed_id=20002, land_ids=[3,4,5,6] }
         → err 1000020「请求参数错误」

✓ 成功：120708a29c01120103 120708a29c01120104
         field2.items = PlantItem{seed_id=20002, land_ids=[3]}
         field2.items = PlantItem{seed_id=20002, land_ids=[4]}
         → err 0，resp 269 B
```

**规则：必须「每块地一个独立 `PlantItem`」。** 一个 `PlantItem` 挂多个 `land_ids` 会被服务端整体拒绝，且不消耗种子。

`seed_id=20002` → 种下后成为植物 `1020002`（白萝卜）。
提示：种子 ID 与植物 ID **不是同一套**（`2000x/4000x/8000x/9000x/1020xxx` 为种子，`1020002` 等为植物）。

### 3. 撒虫 / 撒草

```
req 08b2c38cca04120103          PutInsects
      08 b2c38cca04       field1 host_gid = 1229136306  (好友)
      12 01 03            field2 land_ids = [3]
resp err=0，land:3，limits id10004:1/100  id10003:1/100

req 08b2c38cca04120103          PutWeeds
resp err=0，land:3，limits id10003:2/100
```

注意字段顺序与 `Harvest` **相反**：

```
Harvest   : land_ids=1, host_gid=2, is_all=3
PutInsects: host_gid=1, land_ids=2      ← 反的
PutWeeds  : host_gid=1, land_ids=2      ← 反的
```

**每块地一次请求**，实测间隔 80–160 ms 稳定。

## 三、错误码与额度表（实测）

### 错误码

| code | 含义 | 处置 |
|---|---|---|
| `1000020` | 请求参数错误 | 检查 `Plant` 是否每块地独立 PlantItem |
| `1001036` | 当前植物野草次数达到上限 | 跳过该地块，非全局熔断 |
| `1001037` | 成熟或枯萎阶段不能放虫子 | 跳过该地块（成熟地不可放虫） |
| `1001046` | 今日放虫/放草次数已达上限 | **全局熔断当日该动作** |
| `1001057` | 帮助务农无操作 | 视为 noop，不计失败 |
| `1001024/1001025` | 该地块当前不可施肥 | 跳过该块 |

### 操作额度（`operation_limits`）

| id | 语义 | 实测 |
|---|---|---|
| `10001` | 收获计数 | 收获后 0→1 |
| `10003` | **放草/放虫共用额度** | 撒虫 1、撒草 2、撒草 3（每次 +1） |
| `10004` | 放虫计数 | 洒虫后 1/100 |
| `10015` | 社交道具 | — |
| `10017` | — | 上限 100 |
| `10019` | — | 上限 24 |

**重要**：`10003` 是放虫与放草**共享**的额度（每次操作都 +1），因此「一键撒虫草」的容量要按 `10003` 的总量规划，而不是分别计算。

```powershell

node tools/ops.mjs put-weeds  <gid> [lands]    # 撒草
```

## 五、遗留与建议

**页面刷新会丢失全部注入**（`__netInst`、`__bot`），需重跑 `grab-net.mjs`。建议做成启动脚本，并把 `CDP_CTX` / `MY_GID` 自动探测出来，避免手工填。

**收到后残留 DEAD 植株**：地1 收获后状态为 `DEAD`（枯株），需 `RemovePlant` 铲除才回到空地。实现「收获后自动补种」时应把 `DEAD` 视为可铲除目标。

**写操作超时不可盲目重发**：收获/种植属非幂等操作，超时应改为下轮 `AllLands` 对账。

**`GetAll` 的 `plant` 摘要存在延迟**：撒虫撒草后立刻拉好友列表，`weed_num/insect_num` 未立即更新，但 `Enter` 回包是实时的。巡田决策应以 `Enter` 为准。
