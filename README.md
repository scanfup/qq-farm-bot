# QQ 农场与牧场 Web 控制台

通过 CDP 接入已登录的 QQ 经典农场小游戏，在浏览器里管理农场、牧场和好友，分别配置定时托管。加密、登录态和游戏网络连接由小游戏处理。

## 特性

- **Web 操作**：农场、牧场、优先设置三个页面；自家与好友管理位于对应场景页。
- **独立托管**：农场和牧场分别设置周期、范围和开关，共用串行任务队列。
- **库存优先级**：保存种子与动物顺序，按库存、空地或兼容空位自动补种、补栏。
- **场景日志**：任务与运行日志按农场、牧场分开，显示成功数量、部分拒绝和待核对原因。
- **无需填写凭据**：在微信中正常登录游戏，再从 Web 连接运行时。

## Web 使用教程

### 第 1 步：打开调试通道

按照上方截图教程操作：先打开微信，再启动调试工具，最后打开 QQ 农场。保持调试工具和小游戏运行。

### 第 2 步：进入游戏并获取项目

正常登录小游戏，进入自己的农场。首次使用时在终端执行：

```bash
git clone https://github.com/scanfup/qq-farm-bot.git
cd qq-farm-bot
```

已有项目时直接进入项目根目录。

### 第 3 步：启动 Web 控制台

```bash
# 可选：检查小游戏调试端口
node tools/port-find.mjs

# 启动 Web 服务
npm run web

# 等效命令
# node web/server.mjs
```

终端显示：

```text
QQ 农场 CDP 面板：http://127.0.0.1:3210
```

在浏览器打开 **http://127.0.0.1:3210/**，点击右上角 **“连接运行时”**。连接成功后会显示真实模式、土地、种子库存和好友等数据。启动服务或连接运行时不会自动开启托管。

终端窗口需要保持运行；结束 Node 进程会停止 Web 服务及托管。

### 第 4 步：保存种子与动物优先级

进入 **“优先设置”** 页面，分别设置农场种子和牧场动物：

1. 从下拉框选择品种，点击 **“添加”**，让它出现在下方优先列表中。
2. 用上下移动按钮调整顺序，排在前面的优先使用。
3. 点击对应的 **“保存种子优先设置”** 或 **“保存动物优先设置”**。

只选中下拉框不等于加入列表，也不等于保存。保存优先级只更新配置，不会立刻播种、放动物或开启托管。

默认只使用列表里的可用库存。开启对应的库存兜底选项后，才允许尝试其他可用库存。Web 不自动购买农场种子；动物自动购买默认关闭，只有另行授权并设置预算后才会购买。

### 第 5 步：开启农场托管

进入 **“农场”** 页面，在农场定时托管区域设置：

- 周期：60–3600秒，默认300秒。
- 是否包含全部好友。
- 开启托管开关；修改已开启的配置后点击应用设置。

每轮执行：**成熟收获 → 清理枯株 → 按优先级补种 → 照料 → 可选好友帮忙及偷菜**。若未设置种子优先级，也未允许库存兜底，需在农场页明确选择一个有库存的背包种子。

只有空的主地块会播种，不覆盖正在生长的作物。没有空地时补种数量为0是正常跳过。好友偷菜将全部符合条件、当前账号尚未摘过的地块合并为每位好友一次原生一键请求。

### 第 6 步：开启牧场托管

进入 **“牧场”** 页面，先刷新牧场，确认库存和容量读取成功，再设置周期、好友范围、是否使用库存补草，并开启牧场托管。

每轮执行：**清理 → 可选库存补草 → 开始生产 → 成熟收取 → 按优先级补栏 → 可选好友清理及摘取**。

补栏要求有兼容的空位、已解锁动物及可用库存，或满足明确授权的购买条件。没有空位或优先动物库存不足时会跳过；保存优先级本身不会放置动物。

两个托管开关互相独立。首次开启后等待一个周期才执行，不会马上跑整轮。农场与牧场可以使用不同周期，底层操作仍按队列串行执行。

### 第 7 步：查看结果与停止托管

桌面右侧的 **任务与运行日志** 会随农场、牧场页面切换；窄屏可通过“查看日志”打开。查看每轮数量、业务拒绝明细及暂停原因。需要立即操作时使用页面对应的收获、种植、补栏或一键务农按钮。

农场“一键务农”执行照料和好友操作；完整的收获、清枯株、补种流程由农场定时托管串联，也可使用单独按钮执行。

关闭某个场景的托管开关只停止该场景；已发出的请求允许收尾。关闭浏览器页面不停止托管，服务重启后两边默认关闭，需要重新连接并手动开启。

## 日常运行与异常处理

| 场景 | Web 中的处理方式 |
|---|---|
| 关闭浏览器页面 | 服务和游戏仍运行时，已开启的托管继续 |
| 关闭 Web 终端或重启服务 | 托管停止，重启后默认关闭 |
| 小游戏离线、微信退出或电脑睡眠 | 无法继续操作；恢复游戏后点击“连接运行时” |
| 显示“待核对” | 先恢复连接，再刷新对应场景；核对通过后按需重新开启托管 |
| 设置优先级后没动作 | 确认已添加并保存、托管已开启且已到期，并检查库存及空地/空位 |
| 开关无法开启 | 查看提示的未满足条件，如连接、库存、未保存设置或核对锁 |

写请求超时、断连或结果无法核实时，不自动重发，以免重复写入。历史任务的“待核对”标签会保留，当前是否仍锁定应以页面状态为准。

**已知问题：**牧场好友摘取后的全量刷新如果遇到只读 `AllCells` 超时，即使此前已有确认成功的摘取，当前保守逻辑仍会把任务标为待核对并暂停托管；全局核对锁也可能暂停农场。该问题已定位但尚未修复。`1045220`“已经偷过”本身是明确业务拒绝，会记录后继续；牧场仍需补充已摘玩家过滤。

## 修改本机端口

默认 Web 端口3210、CDP端口62000。若实际端口不同，在启动 Web 前设置（PowerShell示例）：

```powershell
$env:CDP_PORT = '62000'
$env:WEB_PORT = '3210'
npm run web
```

然后访问所设 Web 端口。服务只监听127.0.0.1，不直接支持远程访问。
