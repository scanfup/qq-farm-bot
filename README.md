# QQ 经典农场 挂机助手

> 基于**运行时注入**的 QQ 经典农场（微信小游戏）自动化挂机工具。
> 不破解协议、不处理账号密码、不接触任何登录凭据 —— 通过 CDP 接入正在运行的游戏，复用它自己的网络层。

---

## 特性

- **零凭据**：不输入账号密码，不处理 cookie / token / code，登录完全交给微信客户端
- **不逆向加密**：直接调用游戏自身的网络层，报文体与官方客户端逐字节同构
- **断线自愈**：连接断开、注入丢失均可自动恢复（实测约 20 秒），无需人工干预
- **交互式 TUI**：中文指令、emoji 实时日志、地块与好友状态双栏展示
- **背包选种**：只列背包里真实持有的种子（按配置表 `type=5` 过滤，剔掉金币/化肥/果实），按 `exp/时` 排序挑性价比最高的种
- **无界面模式**：`--once` 单次执行，适合定时任务；`-m` 启动即挂机

---

## 原理

```
微信客户端正常登录并进入小游戏
        │  游戏自己持有登录态、自己心跳、自己反作弊
        ▼
调试端口暴露 CDP 通道（62000）
        │
        ▼
本工具接入 ──► 抓取网络层实例 ──► 注入适配层 ──► 挂机
```

游戏把小游戏网络层封装成了一个方法，**入参是明文 protobuf**，加密 / token / 序列号 / 发送全部由它内部完成：

```js
__netInst.send(
  plainProtobuf,               // ① 明文 Uint8Array，未加密
  'Heartbeat',                 // ② method_name
  callback,                    // ③ 回调 ({meta, body})
  'gamepb.userpb.UserService'  // ④ service_name
)
```

所以本工具**不需要**提取 `tsdk.wasm`、**不需要**复刻登录协议、**不需要**实现任何加解密算法。

## 快速开始

### 第 1 步：暴露调试端口

这一步是为了让微信小程序运行时对外暴露 CDP 端点。**任选一种工具**：

| 工具 | 依赖 | 说明 |
|---|---|---|
| [WMPFDebugger](https://github.com/evi0s/WMPFDebugger) | Node 22+ | 开源，支持平台与版本最全 |
| [WeChatOpenDevTools](https://github.com/JaveleyQAQ/WeChatOpenDevTools-Python) | Python | 开源 |
| WeChatDevTools | 放一个 dll | 「只需放置一个 dll」 |
| First | 免安装 exe | 单文件运行 |

以 WMPFDebugger 为例：

```bash
git clone https://github.com/evi0s/WMPFDebugger
cd WMPFDebugger
yarn
npx ts-node src/index.ts        # 启动调试服务器并注入 hook
```

> **顺序很重要**：先启动调试工具，**再**打开小游戏。反过来的话 hook 注入不到运行时，需要关掉游戏重开。

### 第 2 步：进入游戏

在微信里打开 **QQ 经典农场**，正常进入农场界面。这就是全部「登录」流程 —— 游戏自己持有登录态。

### 第 3 步：启动挂机

```bash
# 检查端口
node tools/port-find.mjs

# 交互模式
node tools/tui.mjs

# 启动即挂机（推荐）
node tools/tui.mjs --yes -m
```

启动成功会看到：

```
[🔌] 桥接就绪 ctx=7
[🔑] gid = 1229136306
[✅] 加载完成：土地 24 好友 14
[🔑] 登录态已就绪，随时可挂机（[m] 或 /挂机）
```

## 功能

### 挂机四件套

挂机循环只执行这四件事 —— 它们**没有额度限制或额度充裕**，可无人值守反复运行：

| 动作 | 说明 |
|---|---|
| **收获** | 收取成熟作物 |
| **种植** | 自动铲除枯株 → 查种子 → 不足则自动购买 → 播种空地（种子由 `/选种` 决定） |
| **偷菜** | 遍历好友，偷取成熟果实 |
| **务农** | 清除自家地块的草虫 + 帮好友清理（**有奖励**，额度近乎无限） |

**撒虫 / 撒草**属于「放置」类操作：共享每日 100 次额度，且会打扰好友，因此**不在挂机循环内**，需手动用指令触发。

### 快捷键

| 键 | 功能 | 键 | 功能 |
|---|---|---|---|
| `/` | 进入指令模式 | `d` | 一键务农 |
| `h` | 一键收获 | `s` | 一键偷菜 |
| `c` | 一键铲除枯株 | `i` | 一键撒虫 |
| `p` | 一键种植 | `w` | 一键撒草 |
| `a` | 挂机四件套 | `m` | 挂机开关 |
| `r` | 刷新 + 自愈 | `q` | 退出 |

### 指令（中文）

按 `/` 进入指令模式，Enter 执行、Esc 取消、`↑` 调出上次指令。

```
【挂机四件套｜无额度限制】
  /收获              收取成熟作物
  /种植 [种子ID]      自动补种空地（种子不足会自动购买）
  /偷菜 [gid]         偷取好友成熟果实（省略 gid = 全部好友）
  /务农              清自家地块草虫 + 帮好友清理（有奖励）

【种子管理｜只从背包选】
  /种子              列出背包里的种子（★ = 当前挂机使用）
  /种子 狗尾         在背包里按名称或 ID 搜索
  /选种 <ID>         切换挂机种植的种子（背包有货才能选）

【自家操作】
  /铲除              清理枯死植株

【放置类｜每日 100 次共享额度，需指定好友 gid】
  /撒虫 <gid>         给好友地块放虫
  /撒草 <gid>         给好友地块放草

【其他】
  /好友              列出好友 gid 与草虫/可偷状态
  /全套              执行挂机四件套一次
  /挂机              开关自动挂机
  /状态              查看桥接与账号状态
  /刷新              刷新数据并执行自愈
  /退出              退出程序
```

### 背包选种

`/种子` 只看**背包**，不列商店全量、不列配置表全量。挂机种什么由 `/选种` 决定，写入 `config.json` 持久化，下次启动自动沿用；也可以用 `--seed <ID>` 在命令行覆盖。

背包接口返回的是**全部物品**（金币、化肥、果实、黄金变异植物…），所以列表按配置表 `type` 字段过滤，只保留 `type = 5` 的种子：

| type | 含义 | 例子 |
|---|---|---|
| 2 | 货币 / 化肥容器 | `1001` 金币、`1012` 有机化肥容器 |
| 3 | 经验 | `1101` 种植经验 |
| 5 | **种子** | `20516` 狗尾草种子 |
| 6 | 果实 | `40516` 狗尾草 |
| 17 | 黄金 / 变异植物 | `1040516` 黄金·狗尾草 |

不过滤的话，背包里 99481 个化肥容器、37534 金币都会被当成「种子」列出来。

实测输出（账号 lv17，背包恰好 4 种种子）：

```
[13:13:00] ..  ━━ 背包种子 共 4 种 ━━
[13:13:00] ..    ID       作物           数量   单价     生长   经验  exp/时  等级
[13:13:00] ..    29004    泡泡棉花糖     22     ≈12000   12.0h  7680  640     lv200
[13:13:00] ..    26030    月下美人       48     ≈2000    12.0h  1680  140     lv41
[13:13:00] ..    21625    枸杞           20     ≈2000    12.0h  1680  140     lv41
[13:13:00] ..    20516    狗尾草         422    ≈1000    12.0h  1440  120     lv21
[13:13:00] ok  当前挂机种子: 20002 白萝卜（背包 0 个）
```

`exp/时` = 单位时间经验收益（`经验 × 3600 / 生长秒数`），按它**降序**排列，是长效挂机选种的主要依据。

单价有两个来源：商店列表收录的显示**实时售价**；未收录的显示带 `≈` 的**配置表基准价**。已核对的 8 个基础种子中商店价恰为基准价 2 倍（白萝卜 1→2、草莓 1120→2240），但 `≈` 值不保证等于实际售价。

种子表落在 `tools/seed-map.json`，共 **210 条**：`Plant` 配置表提供生长时长 / 经验 / 果实，`ItemInfo` 配置表补全价格与解锁等级。解包链路：Cocos `TextAsset` → Base64 → XOR（循环密钥）→ JSON，见 `docs/` 下的配置解密说明。

挂机时背包种子不足会自动去商店购买；买不到（未上架 / 等级不够）只在首次提示，之后静默，避免每轮刷屏。种子耗尽会提示用 `/种子` → `/选种 <ID>` 换种。想让挂机的种子即使背包为 0 也继续种，用 `/种植 <ID>` 或 `/选种` 后依赖自动购买即可。

### 自身识别

登录账号的 gid **不能只靠心跳解析**。心跳 hook 匹配的是「gid + 版本号字符串」，而**访问好友农场时的请求也带这个组合**——站在好友的农场里启动或刷新，解析到的是**好友的 gid**，不是登录账号。

后果很隐蔽：

- 自己会被当成好友，挂机时反复尝试进入自己的农场并返回 `1000020 请求参数错误`
- 真正的自己被排除在所有好友操作之外，自己地块上的草虫永远不会被处理，日志里也从不出现

可靠判据是好友列表里的 **f9 农场摘要**。这层摘要给的是该好友的草 / 虫 / 可偷状态，而**自己那条不携带摘要**（不需要看自己的状态）。所以：

```
好友列表里唯一没有 f9 摘要的条目 = 自己
```

`refresh()` 每次都会据此校正，并在发生修正时明确打印：

```
[13:25:15] ERR 🔑 身份校正: 1116844998 → 1229136306（shilin）
[13:25:15] ERR     1116844998 是当前正在访问的好友，不是登录账号
```

心跳解析只负责等待时机与给出候选值，不作为身份的唯一来源。

### 务农的两个方向

`/务农` 同时覆盖自家的地和好友的地，两者是同一个 `Farming` 接口，只差场景字段：

| 目标 | 数据源 | 请求 |
|---|---|---|
| 自己的地 | `AllLands`（服务端按登录态返回，不需要进访客模式） | `Farming(land_ids, host_gid=0, field_4=0)` |
| 好友的地 | `visit.Enter` 回包逐块扫描 | `Farming(land_ids, host_gid=好友, field_4=2)` |

自家务农额度同样近乎无限（实测限额 `id10005/6/7` 均为 `999999999`）。副产地（`masterLandId != 0`）不支持单独操作，遇到时会提示需在主地处理。

**判定依据**：务农涵盖除草、除虫、浇水三类，判定有两个来源：

| 来源 | 数据 | 说明 |
|---|---|---|
| 好友放置 | `weed_owners`(f12) / `insect_owners`(f13) | 只记录**谁放的**，自然长出的草虫这里没有记录 |
| 自然到期 | `phases[].dry_time`(6) / `weeds_time`(7) / `insect_time`(8) | 服务端给每个阶段下发的**旱 / 草 / 虫到期时间**（绝对 unix 秒），到点即生效 |

只看 `owners` 会漏掉全部自然发生的旱草虫——这正是"好友农场明明有得务农却报无可用"的根因。注意要取**当前阶段**（最后一个 `begin_time <= now` 的条目，`phases` 里同时含未来阶段的预测）的到期时间。

好友务农**全量扫描**，不用好友摘要做硬预筛：摘要会虚报（某轮标记 7 个好友有草虫，实际只有 3 个），被预筛掉的好友连日志都不留。摘要现在只作对照打印，每个好友的候选明细（草/虫/旱，及其中有多少来自好友放置）都会输出。

### 启动参数

```bash
node tools/tui.mjs                    # 全屏 TUI（交互面板）
node tools/tui.mjs --cli              # ★ CLI 模式：纯滚动输出 + 指令输入（推荐）
node tools/tui.mjs --cli --interval 30
node tools/tui.mjs --daemon           # 守护模式：无任何界面，仅写日志
node tools/tui.mjs --once             # 无界面跑一轮后退出（定时任务）
node tools/tui.mjs --gid <n>          # 指定 gid，省去探测等待
node tools/tui.mjs --port <n>         # 指定调试端口（默认 62000，可自动发现）
node tools/tui.mjs --seed <n>         # 指定种植种子 ID
node tools/tui.mjs --log-dir <path>   # 指定日志目录（默认 ./logs）
```

### 三种运行模式怎么选

| 模式 | 界面 | 适用场景 | 终端兼容性 |
|---|---|---|---|
| `--cli` | **滚动日志 + `指令>` 提示符** | **日常使用（推荐）** | **最好**，不依赖任何特殊转义序列 |
| `--daemon` | 无 | 服务器 / 长时间无人值守 | 无要求 |
| 默认（TUI） | 全屏面板 | 想同时看地块与好友状态 | 依赖 alternate screen，部分终端有兼容问题 |

> **如果你的终端是全屏 TUI 卡死，请改用 `--cli`。** 全屏模式依赖 `\x1b[?1049h`（alternate screen）与光标定位，PowerShell / 传统 conhost 对这类序列支持不佳时会导致界面假死。CLI 模式只做滚动打印，从根本上规避该问题，功能完全一致。

## 断线处理

| 场景 | 需重新登录吗 | 处理方 |
|---|---|---|
| 网络抖动 / 请求超时 | 否 | 游戏网络层自动重连并重取凭据 |
| 游戏页面刷新 / 重启 | 否 | **本工具自动重抓注入（约 20 秒）** |
| 挂机脚本崩溃 | 否 | 重跑脚本即可（注入仍在游戏内） |
| 微信客户端关闭 | 是 | **需人工重开客户端并进游戏** |

启动时 `Bridge.ensure()` 会自动完成：连接 CDP → 探测游戏上下文 → 抓取网络层实例 → 注入适配层 → 解析 gid。注入丢失时会自动重来。

## 运行方式与限制

### 需要保持游戏进程运行（但不必在前台）

本方案通过 CDP 接入**正在运行**的游戏运行时。所以：

| 状态 | 能否挂机 | 说明 |
|---|---|---|
| 游戏在前台 | ✅ | 正常 |
| **游戏窗口最小化** | ✅ | **实测可行**，心跳与 ACE 上报照常 |
| 游戏被其他窗口遮挡 | ✅ | 同上 |
| **手动关闭小游戏** | ❌ | 运行时销毁，挂机停止 |
| 微信客户端退出 | ❌ | 同上 |
| 电脑关机 / 睡眠 | ❌ | 进程停止 |
| 挂机脚本崩溃 | ✅ | 注入仍在游戏内，重跑脚本即可 |

**实测依据**：最小化状态下采样两次，35 秒内 `clientSeq` 从 1464 增长到 1472，`_state` 保持 5（已连接），说明心跳与反作弊上报在后台正常轮转。

**所以日常用法就是**：进一次游戏 → 最小化 → 启动挂机 → 该干嘛干嘛。电脑保持开机即可。

### 为什么不能完全脱离游戏

游戏侧的**登录凭据是一次性的**，且由客户端在连接时现场生成：

```
微信 wx.login()  ──►  一次性 code  ──►  拼进 WSS 连接串
                                          wss://gate-obt.nqf.qq.com/prod/ws?...&code=xxx
```

这个 `code` **只存在于客户端运行时内存中**（HTTP 抓包永远看不到它），且每次重连都要重新获取。所以：

- **脱离游戏窗口** —— 可以（本文方案）
- **脱离微信客户端** —— 不行，一旦断线就没有新的 `code` 来源

理论上还存在「外部进程直连 WSS」的路线（自己实现加密层 + 协议栈），但它同样需要从微信获取 `code`，且要自行复刻反作弊上报，工程量与风险都远高于本方案，因此本项目未采用。

### 长时间运行的注意点

- **游戏页面别刷新**：刷新后注入会丢失，工具会自动重抓（约 20 秒），无需干预
- **微信别重启**：重启后需重新打开游戏页面
- **调试工具保持运行**：它负责维持 CDP 端点，关掉就断链
- **建议定期看一眼**：TUI 顶部有连接状态、运行时长与自愈次数

## 常见问题

**Q：提示 CDP 连接失败**
1. 调试工具没启动
2. 工具比游戏启动晚 → 关掉游戏重开
3. 62000 被其他调试客户端占用（如浏览器 devtools 页面）→ 关掉它
4. 端口不是 62000 → `node tools/port-find.mjs` 自动查找

**Q：62000 是单客户端独占吗**
是。有别的调试器连着时，脚本能建立连接但收不到消息。同一时刻只保留一个客户端。

**Q：为什么必须装调试工具**
微信小程序框架（WMPF）的 Remote Debug 默认关闭且有校验，必须有一步注入才能解开。这一环无法从脚本侧绕过。但**工具可任意替换**，脚本侧无需改动。

**Q：微信更新后失效**
WMPF 版本随之变化，需等调试工具适配新版本号。

**Q：能关掉微信跑吗**
不能。关掉客户端等于断掉运行时，挂机随即停止。需要保持开机 + 游戏页面打开。

```
.
├─ README.md
├─ package.json
└─ tools/
   ├─ tui.mjs            # 命令行 TUI（交互面板 / 无界面模式 / 中文指令）
   ├─ core.mjs           # 核心桥接层：CDP、上下文探测、注入抓取、自愈、端口自动切换
   ├─ farm.mjs           # protobuf 编解码、请求构造器、地块/背包/商店解析
   ├─ seed-map.json      # 种子表：210 种作物的名称/生长时长/经验/价格/解锁等级/果实
   ├─ port-find.mjs      # 调试端口自动发现
   └─ probe/
      └─ inject_bot.js   # 注入到游戏运行时的适配层
```
